## Контекст

AI-first authoring должен ускорять создание концептов мира, ландшафтов, материалов, предметов, оружия, брони, персонажей и существ. Генеративные image и image-to-3D services при этом являются network/account/GPU-зависимыми, могут менять model revision без контроля engine, возвращать недетерминированные, технически невалидные или юридически непрозрачные bytes и не гарантируют gameplay semantics скрытых поверхностей, collision, navigation, LOD или streaming.

Если tool output публикуется напрямую, он создаёт второй asset source of truth, обходит `NeutralAuthoringModel`, license/provenance validation и human review. Если конкретный provider попадает в public contract, engine становится зависим от vendor account, terms, quotas и model lifecycle. Если весь landscape преобразуется из concept image в один mesh, визуальная правдоподобность подменяет проходимость, chunk ownership и RPG affordances.

## Решение

- AI content generation MUST быть development-only artifact-first pipeline внутри Asset & Tool Chain, а не runtime gameplay capability.
- Public boundary MUST быть engine-owned и provider-neutral: versioned generation recipe/job/result/provenance/normalization manifests, `AgentChangeSet`, `NeutralAuthoringModel`, diagnostics и evidence. Provider model IDs, SDK objects, account/session handles и CUDA/DCC types не входят в public contracts.
- Generative adapter MUST исполняться как optional short-lived external `generation-worker` с explicit input/output roots, quotas, deadline, network capability и atomic result publication. Он не входит в `game`, `headless` или `capture-worker` и не является `ai-host` runtime capability ADR-005.
- First-party 2D authoring adapter MAY использовать OpenAI ImageGen через доступную subscription surface. Subscription access не считается unattended API contract, CI credential или обязательной capability. Отдельный API adapter требует собственного credential/network/terms review, но реализует те же engine manifests.
- First-party image-to-3D research adapter MAY использовать Pixal3D. Он имеет статус `Proposed`, pin exact code commit, checkpoint hashes и dependency SBOM и выдаёт только untrusted GLB/mesh candidate.
- `TripoSR` MAY служить low-resource comparator/fallback за тем же boundary. Ни Pixal3D, ни TripoSR не являются runtime dependency или Accepted technology до своих gates.
- Concept images мира и landscape MUST быть visual constraints/reference, а не authoritative world geometry. Playable world topology строится из typed world recipe, deterministic procedural stages, curated/generated asset instances и explicit traversal/streaming/RPG constraints.
- Generated object/character/material output MUST пройти deterministic normalization, bounds/schema/provenance validation и common cooker SPEC-03. Direct publish generated bytes → runtime bundle запрещён.
- Generative inference MAY быть недетерминированным только в reproducibility class `ArtifactFixed`: exact accepted input/output bytes, provider/tool metadata и hashes фиксируются, а downstream normalization/cooking детерминированы. Procedural official world recipes используют `RecipeDeterministic`; `EphemeralPreview` не может быть опубликован.
- Generated bytes, prompts with protected/private content, model outputs, caches и worker runs MUST находиться во внешнем artifact root и не коммититься в engine repository. Project source хранит versioned recipes, redacted metadata и content-addressed references согласно policy.
- Promotion candidate в project MUST проходить `AgentChangeSet` с exact base/input/output/provenance/normalization/evidence hashes. Observable output всегда получает `HumanReviewRequired`; automatic mesh/world/license/replay failure не может быть waived review.
- Engine conformance MUST использовать offline deterministic fixture adapter. Отсутствие OpenAI account, network или NVIDIA generation GPU не блокирует runtime, cooker, validator, existing-content build или vertical slice; live adapter gate получает `AwaitingCapability`, а не synthetic `PASS`.

## Рассмотренные варианты

- **Одна model text/image → готовый игровой мир** — `Rejected`: visual shell не определяет topology, POI reachability, navigation, collision, streaming budgets, PersistentId ownership и gameplay affordances.
- **OpenAI/Pixal3D types в public contracts** — `Rejected`: связывает engine schema с vendor lifecycle и нарушает replaceable adapter boundary.
- **AI output сразу в cooked bundle** — `Rejected`: обходит untrusted-input validation, provenance, deterministic cooking и human review.
- **Generative inference обязана побитово воспроизводиться** — `Rejected`: managed services и GPU models могут не давать такой гарантии. Authoritative boundary переносится на exact candidate bytes и deterministic downstream processing.
- **Subscription ImageGen как CI/unattended API credential** — `Rejected`: product entitlement не является стабильным machine API contract; автоматический API route рассматривается отдельно.
- **Cloud-only 3D generation** — `Rejected` как baseline: optional cloud adapters допустимы после privacy/terms/network gate, но local/manual/fixture fallback остаётся полным.
- **Full scene editor как обязательный orchestration surface** — `Rejected` для v1: CLI/JSON normative, GUI/MCP только projections.

## Последствия

Asset & Persistence Team получает дополнительный source-side manifest family и generation orchestration service, но единственный runtime asset source остаётся `ContentManifest` + cooked bundles SPEC-03. Developer Experience предоставляет complete CLI/JSON path и offline fixture adapter. Security классифицирует prompts, source images, provider terms, model/checkpoint/data licenses и generated output отдельно. Verification запускает geometry/world automatic gates до capture/review.

Качество generator оценивается не gallery impression, а долей candidates, прошедших deterministic normalization, target budgets и gameplay/world scenarios без ручного исправления. Model/provider update создаёт новую evidence revision и не меняет ранее утверждённые artifact hashes.

## Technology gates

| Candidate | Gate | Threshold | Evidence | Fallback |
|---|---|---|---|---|
| OpenAI ImageGen subscription adapter | `IMAGEGEN-P1` | 50 typed recipes across concept/world/object/character/material profiles: 100% success or classified failure; exact request/result hashes and reported surface metadata; explicit network consent; 0 partial publish or secret/protected-data leak | recipe/job/result manifests, account-surface capability record, output hashes, redaction/network/fault report, review samples | user-authored/imported reference images; live generation `AwaitingCapability` |
| Pixal3D | `IMG3D-P1` | exact pinned commit/checkpoints/SBOM; curated 60-image corpus; accepted candidates meet profile mesh/PBR/bounds quotas after deterministic normalization; 100% invalid outputs classified/rejected; 0 sandbox escape/partial publish | tool/model manifest, hardware profile, GLB/normalization reports, dependency/license SBOM, failure corpus and review media | TripoSR comparator, manually authored mesh or no generated 3D |
| TripoSR | `IMG3D-F1` | exact pinned code/model/SBOM; same low-resource corpus and validation semantics; quality/runtime claims limited to measured profile | model/tool manifests, normalization metrics, hardware/timing and license report | manually authored mesh or generation unavailable |

## Supersession

Разрешение runtime/network-required generation, direct generated-output publication, provider types в public contracts, agent self-approval или whole-world visual mesh как gameplay authority требует нового superseding ADR. Замена конкретного generator за теми же manifests/gates является evidence update, а не architecture change.
