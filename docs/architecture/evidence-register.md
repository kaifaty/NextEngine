Реестр отделяет внешние факты от архитектурных решений. Статус технологии означает решение Next Engine, а не оценку качества проекта. Перед bootstrap implementation владелец MUST повторно проверить release, license и platform support; изменение факта обновляет эту таблицу, изменение решения требует ADR.

## Правила revalidation

Research papers, перечисленные в профильных ADR как evidence composability или training methods, не являются technology dependencies и не получают самостоятельный статус в этой таблице. Architecture принимает только engine-owned contracts и gates; конкретный research method остаётся заменяемым.

- `Proposed` кандидаты MUST быть pinned по exact version/commit и checksum в PoC manifest.
- License classifier MUST проверить SPDX expression, transitive dependencies и redistribution artifacts.
- Shipping-платформенное утверждение считается доказанным только native Windows/Linux run; bootstrap Mac-host claim проверяет локальный HOST-MAC-01 и не подменяет shipping matrix.
- Если новая версия меняет API, license, model format или serialization, dependency owner MUST открыть evidence change и оценить необходимость superseding ADR.
- Внешний факт без primary source не может переводить технологию из `Proposed` в `Accepted`.
