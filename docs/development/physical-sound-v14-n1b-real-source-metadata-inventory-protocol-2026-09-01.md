## Question

Can current official ObjectFolder Real, RealImpact and ObjectFolder 2.0
publication surfaces be reduced to a repeat-exact object/source/member and
acquisition-cost inventory without decoding PCM or numeric force values, while
making source-revision drift and previously exposed objects explicit?

N1b inventories candidates. It does not choose train, development, validator
or shadow roles, grant `training_usable`/`evaluation_complete` credit, inspect
audio quality, train a model or authorize N2. N1c alone may freeze roles after
the inventory is immutable.

## Frozen inputs

All source and generated bytes remain in the external experiment store. The
offline builder receives these exact regular files and rejects symlinks,
unknown files, hash mismatch, replacement output, noncanonical JSON or an
input over its declared bound.

The N1a descriptor must name Dataset Contract V1 and preserve the
`4/1/1/1/1` Glass/Wood/Metal minimum. N1b jointly binds that exact descriptor
and the exact historical ledger as separate inputs; it cannot silently
substitute either one.

## Publisher identities and revision drift

N1b retains four distinct source revisions:

1. `objectfolder_real_current` — the current rendered 100-row table plus the
   cached compact benchmark members;
2. `objectfolder_real_historical_d058` — the pinned historical 100-row table;
3. `realimpact_fca2` — the 50 publisher object names and one ZIP per object;
4. `objectfolder2_3c6c` — 1,000 synthetic Object Files in ten batch archives.

The historical and current ObjectFolder tables disagree in the `91…100`
range. RealImpact names follow the historical numbering (`93_GreenGoblet`,
`94_GlassGoblet`, and so on), while the current ObjectFolder table gives those
numbers different names. Therefore a numeric prefix is **not** a physical-
object alias by itself.

The inventory records an alias edge only when the publisher revision, object
ID and normalized name/material evidence agree. Conflicts become
`ambiguous_revision_identity`; they neither merge physical groups nor create
evaluation credit. ObjectFolder 2.0 IDs are a separate synthetic namespace and
are never aliased to ObjectFolder Real by number.

## HTTP acquisition snapshot

The committed runner has an explicit `acquire` stage. It may issue only
metadata requests to these exact HTTPS endpoint families:

- ten ObjectFolder Real archives
  `audio_data_1_10.tar.gz` through `audio_data_91_100.tar.gz`;
- ten ObjectFolder 2.0 archives `ObjectFolder1-100.tar.gz` through
  `ObjectFolder901-1000.tar.gz`;
- the 50 RealImpact ZIPs named by the frozen `object_names.txt`.

At most `70` requests are allowed. Redirects must stay on
`download.cs.stanford.edu` or `downloads.cs.stanford.edu`. A response records
only requested URL, final URL, status, `Content-Length`, `ETag`,
`Last-Modified`, `Accept-Ranges` and acquisition time; the canonical build
removes wall-clock time from its outputs. No archive response body is stored.
A server that cannot provide a trustworthy non-negative length is reported as
`identity_unavailable`, not probed with a bulk download.

Tests use an offline synthetic snapshot. The repeat-exact evidence build never
uses the network; it consumes one frozen snapshot twice.

## Metadata-only archive traversal

The offline builder may hash complete cached files and traverse gzip/TAR
headers to recover member names, types and declared uncompressed sizes. It may
parse the split and scale JSON. It must not extract or parse WAV payloads, NPY
array headers/data, object vertices, contact coordinates or force metadata.

For the compact benchmark the permitted structural facts per object are:

- membership in the published split and contact count by split role;
- presence/count of `.wav`, contact `.npy` and geometry `.npy` members;
- presence of one scale key;
- member-name root and declared byte-size totals.

The README claim of `53` real objects is retained as publisher prose. The
actual frozen split object count is an independent exact observed fact; a
mismatch is reported and never repaired by inventing rows.

Remote gzip/TAR archives have batch-level acquisition granularity. Their
member completeness remains `member_preflight_required` until a later bounded
N1c acquisition. RealImpact ZIPs have object-level granularity; their central
directory/member completeness also remains sealed in N1b.

## Inventory schemas

The top-level output schemas are:

```text
nextengine.experimental-physical-sound-source-inventory.v1
nextengine.experimental-physical-sound-source-cost-report.v1
nextengine.experimental-physical-sound-v14-n1b.report.v1
```

`inventory.json` contains sorted `sources`, `archives`, `objects`,
`alias_edges`, `publisher_claims`, `discrepancies` and `access`. Each source
and object binds its exact publisher revision. Each object row contains:

```text
inventory_object_id
source_id
publisher_object_id
publisher_name
publisher_material
material_family
source_tier
structural_presence
member_root_sha256
exposure
alias_status
candidate_state
reason_codes
```

Only exact `Glass`, `Wood`, `Steel` and `Iron` publisher materials map to the
V14 families; Steel and Iron map to `Metal`. Other values have null
`material_family`. RealImpact material is inherited only from an unambiguous
match to its own historical ObjectFolder revision; a name token such as
`Metal` is not authoritative by itself.

Candidate states are deliberately pre-contract:

- `metadata_candidate` — publisher material is in scope and the metadata
  route has the minimum structural axes visible for later member preflight;
- `member_preflight_required` — in-scope publisher row exists, but remote
  member structure is still sealed;
- `source_ood` — out-of-scope material, identity ambiguity, missing structural
  metadata or unavailable archive identity.

These states are not N1a quality masks and do not authorize any role.

Exposure is computed by querying the exact M1b object-parent identities for
the current row and only its proven alias edges. The inventory carries the
full observed-role union and state; previously opened objects remain visible
but cannot later become protected candidates.

## Cost model

`costs.json` reports, by source and material:

- already-cached archive bytes and metadata bytes read by N1b;
- remote archive bytes represented by exact HTTP identity;
- minimum archive bytes required for a later member preflight;
- request count and acquisition granularity (`object`, `batch_10`,
  `batch_100` or `cached`);
- candidate objects per acquisition unit;
- `pcm_values`, `force_values` and `protected_signal_values`, all zero.

For a remote ZIP, later central-directory range cost may be estimated only
after `Accept-Ranges: bytes`; otherwise the conservative preflight cost is the
whole object archive. For gzip/TAR, the conservative member-preflight cost is
the whole containing batch. Estimated values are labelled estimates and never
replace HTTP `Content-Length`.

N1b is bounded to the frozen `70` endpoint identities and existing cached
files. It cannot download a remote archive merely to improve coverage.

## Access counters and hard guards

The repeat build publishes these independent counters:

```text
network_requests = 0
network_archive_body_bytes = 0
cached_archive_bytes_hashed
cached_archive_bytes_traversed
tar_member_headers_seen
json_scalar_values_decoded
pcm_sample_values_decoded = 0
force_sample_values_decoded = 0
protected_signal_values_decoded = 0
wav_headers_parsed = 0
npy_headers_parsed = 0
source_payload_members_extracted = 0
```

Archive member names must be normalized, relative and unique. Links, devices,
path traversal, duplicate JSON keys, nonfinite values, unknown schemas,
unexpected endpoint URLs, duplicate object IDs, malformed materials and a
source file changed during hashing all fail closed.

The builder writes atomically to a fresh external directory:

```text
inventory.json
costs.json
report.json
```

Two builds from the same exact input snapshot must be byte-identical.

## Decision and N1c boundary

N1b passes as:

```text
N1B_METADATA_INVENTORY_PASS / N1C_MEMBER_PREFLIGHT_NEXT
```

only if all inputs and endpoint identities are bound, all structural and
zero-signal guards pass, and the report gives an exact potential candidate
count for Glass/Wood/Metal without assigning roles. Less than eight potential
physical groups for any material is reported as
`N1B_COVERAGE_INSUFFICIENT_FOR_FULL_SHAPE`; it is a valid repeat-exact result,
not permission to weaken N1a or decode signal.

N1c must preregister the smallest acquisition units needed to resolve member
completeness and revision ambiguity, then freeze object/recording groups and
roles. It may narrow the first domain or stop N1 if the exact physical-group
minimum cannot be met. No candidate ranking may depend on waveform content.
