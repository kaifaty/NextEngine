external-source modal payload object?

## Validation order

Before publication the owner must:

1. validate its canonical profile and tracked owner/protocol/D0 bindings;
2. reject missing, extra, symlinked, oversized or hash-mismatched inputs;
3. validate the exact upstream schemas and terminal decisions;
4. prove both D0 sources are untrusted and therefore contribute zero modal rows;
5. group Clatter rows only by canonical Recipe V3 modal-head values, never by
   filename, nominal label or random render;
6. prove every C0R record appears in exactly one matching role projection;
7. prove every IETeasy row is generator-train and projection-consistent;
8. reject record-ID or physical-parent collisions between the two real sources;
9. keep each project/source component in one role family;
10. verify all content references are bounded, relative and SHA-256 addressed,
    without opening the referenced object;
11. reproduce the frozen record/parent/project/role/planning counts.

Any failure occurs before the output directory is published. Unknown fields in
the D1 profile fail closed; upstream artifacts are accepted only at their exact
bound hashes, so their richer historical schemas do not become a new public
contract.

- path-neutral identities and hashes for all twelve source artifacts;

- 36 empirical-prior groups, each with its canonical modal-head hash and sorted

target as Recipe V3. It preserves their schema/hash references for B0 adapters;
missing Recipe V3 coordinates remain missing.

## Access and authority

The owner is network-free and imports no audio, NumPy, ML or runtime package.
It records metadata bytes/files read. These counters remain zero:

- content objects opened or copied;
- target values decoded;
- PCM/audio/waveform values decoded;
- new external-source modal payload values decoded;
- model or protected values read;
- network requests.

The compiler does read and canonicalize the `3,528` inline modal control
scalars already present in the admitted C0 metadata so that it can form the 36
value-distinct control groups. That bounded metadata access is reported
separately and is not synthetic-teacher or acoustic payload access.

D1 grants only `v46_b0_control_tournament`. It creates no new parent/project
credit, does not make the five validator rows sufficient, and does not authorize
training. Authored clips remain the only product path.
