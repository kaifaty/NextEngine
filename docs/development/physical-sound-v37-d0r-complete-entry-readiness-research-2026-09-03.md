## Problem

T0 made the synthetic target function exact, but a complete-entry audit found
that this alone does not make D0 preregistered. F0 names several evaluation
paths without fixing every numerical choice required to execute them. The
clearest example is `continuous-local-interpolation-v1`: its declared
anisotropic RBF family does not specify the distance coordinates, bandwidth
rule, zero-distance behavior or reduction order. The fixed RBF ridge names an
unregularized intercept but does not define its exact design matrix and solver.

The same incomplete pattern exists at adjacent layers:

- optimizer name does not state betas, epsilon, update/batch schedule and exact
  gradient accumulation;
- metric thresholds exist, but branch aggregation, eligible control sets,
  denominator-zero rules and ablation-to-stratum mapping are not exhaustive;
- hard-gate names exist, but the executable witnesses and gate precedence are
  not bound into one official owner;
- publication semantics are proven by X0, but the eventual target-aware owner
  has not executed all paths before capability creation.

No V37 truth target has been evaluated. The finding is therefore a pre-access
contract defect, not a scientific reject and not a reason to allocate fresh
roles.

## External evidence

The bounded research cycle used current primary guidance only to choose the
closure standard, not to change the frozen scientific hypothesis:

- the [PLOS Biology preregistration study](https://journals.plos.org/plosbiology/article?id=10.1371/journal.pbio.3000937)
  scores a plan as fully restrictive only when choices are specific, precise
  and exhaustive; it identifies analysis software/packages and assumption
  handling among frequently under-specified degrees of freedom;
- [NeurIPS 2026 evaluation guidance](https://neurips.cc/Conferences/2026/EvaluationsDatasetsReviewerGuidelines)
  requires evaluation methods and metrics to be detailed enough for independent
  replication and treats code as mandatory for reusable executable artifacts;
- the [ACM artifact-review policy](https://www.acm.org/publications/policies/artifact-review-and-badging-current)
  distinguishes repeating the same measurement procedure from independently
  validating a result. V37 D0R can establish the former; the later real-data
  validator remains a separate V0 certificate.

These sources support one bounded conclusion: a list of names and thresholds is
not enough. The complete measurement procedure, environment and executable
artifact must be fixed before data access.

## Selected D0R closure

D0R is a value-free implementation-conformance stage, not another scientific
role. It must create three mutually binding artifacts:

1. **Complete-entry profile.** Freeze optimizer defaults and row schedule;
   exact nearest/local/ridge algorithms; metric reductions, eligible controls,
   ratio-zero policy and every ablation/stratum gate; hard/resource precedence;
   output schema and allowed terminal set.
2. **Actual D0 owner.** The same function used later with an official provider
   must own materialization, target-aware training, all controls, predictions,
   metrics, hard/resource gates and atomic terminal publication. No alternate
   official entry point is allowed.
3. **Readiness seal.** Run the owner twice on all frozen structural rows with
   nonzero artificial targets generated by a same-family artificial teacher.
   Bind exact trees, owner/profile/environment hashes, E0/T0 seals, access
   receipts and all terminal/failpoint mutations. Official capabilities remain
   impossible during this stage.

The artificial teacher may make the natural rehearsal pass by construction so
every candidate/freeze path executes. That is mechanics evidence only. Its
values cannot set or relax a scientific threshold, and it cannot be cited as
QSO quality.

## Complete degree-of-freedom checklist

D0R does not seal until every row below has an executable expected result:

| Layer | Required closure |
| --- | --- |
| Identity | Profile, owner, A0/C0/X0/E0/T0/publisher dependencies and frozen environment |
| Access | One provider kind/namespace, exact role order, target counters, no H0 or real/protected/network access |
| Training | Model/seed order, AdamW betas/epsilon/weight decay, 96-step cyclic batch schedule, 512-row accumulation, loss scaling and clip order |
| Nearest | Partition key, distance columns, lexicographic tie behavior and exact target gather |
| Local RBF | Same partition, distance columns, per-query positive-distance median bandwidth, exponent, normalization and no-support policy |
| Ridge | Exact integral design columns, intercept placement, diagonal regularization, float64 solve and singular/nonfinite policy |
| Metrics | Axis/stratum RMSE, candidate/control sets, best-control and each-control ratios, exact-zero denominator policy and gate conjunction |
| Ablations | Field-only/query-only/no-topology/no-interaction cells and required worsening per declared strata |
| Hard gates | Finite/bounds, structural commitments, branch reachability, P1 multiplicative invariants, forbidden-access counters and target/row alignment |
| Resources | Wall/RSS/output/parameter accounting and decision precedence |
| Publication | Pass-only bundle/freeze; reject-only evidence; owner-fault evidence; atomic failpoints; stdout/tree A/B equality |

## Stop and rollback rules

- E0-only or T0-only capability creation is forbidden; both seals and the D0R
  readiness seal must verify first.
- Any D0R ambiguity or artificial divergence is repaired only while official
  access counters remain zero, followed by a fresh readiness seal.
- Once official D0 begins, D0R owner/profile/seal, scientific thresholds, role
  identities and retry policy are immutable.
- Any scientific reject, resource reject, post-access owner fault or A/B
  divergence closes QSO-v0. H0 remains unopened.
- D0R does not alter S0/S1/V0, internet-only acquisition, offline-only ML or the
  authored fallback requirement.
