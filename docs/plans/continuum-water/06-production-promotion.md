# W6 — Production promotion

## Outcome

Convert passing W1–W5 evidence into one bounded production decision. Earlier
packages do not make the track current by accumulation.

## Required promotion change

Create one consumer-backed Accepted ADR that narrowly supersedes the current
PhysX-only wording only as needed to admit CPU DFSPH as a Physical
Embodiment-owned water component. It must preserve PhysX as the sole writer of
rigid/articulation state and name the authored dry pre-activation fallback.

In the same coherent change:

- update SPEC-02/03/21/25/26/30 and SPEC-36;
- add only the W4-consumed current-only public records;
- promote the composite `PhysicsWorldCheckpointV3` closure proven by W5;
- bind region/profile/content/coupling hashes into project/save/replay closure;
- update schema registry, routing, traceability and the main roadmap;
- add production adapters/composition while keeping vendor types private;
- preserve identical `game`/`headless` command, failure and persistence paths.

No migration reader is required for unshipped alpha continuum records. The
outer current version rejects anything else before nested decode or mutation.

- `CONTINUUM-WATER-REF-P1 = PASS` for W0/W1;
- W2 worker/order exactness and 50k THOTH performance PASS;
- `CONTINUUM-COUPLING-P1 = PASS` for one-pass reaction and failures;
- W4 `play`/headless production-command and presentation-independence PASS;
- `CONTINUUM-PERSISTENCE-P1 = PASS` for exact active continuation;

- exact canonical water/rigid/composite roots on both shipping targets;
- `performance` using exact THOTH fingerprint and compatible baseline;
- `fast`/host check appropriate to the cross-cutting public-contract change.

WG/GPU correspondence is not required for CPU production promotion. If a GPU
mirror is shipped as optional diagnostics or presentation quality, its own
platform/correspondence evidence is additive and still grants no authority.

## Public contract guard

Admit only:

- `ContinuumRegionDefinitionV1`;
- `ContinuumWaterProfileV1`;
- `ContinuumWaterCanonicalStateV1`;
- `ContinuumBodyReactionBatchV1`;
- `ContinuumPresentationSnapshotV1`;
- `PhysicsWorldCheckpointV3` with exact water owner segment;
- the exact rigid-boundary/continuum coupling-material mapping used by the
  basin.

Reject generic solver/plugin APIs, raw sample/grid mutation, public backend
handles, broad fluid queries, cross-region protocol, sleep format, surface
render contract and terrain fields. They require demonstrated consumers.

## Stop conditions

Do not promote when any of the following holds:

- a correctness threshold passes only after post-hoc tolerance changes;
- same-target or Windows/Linux canonical roots differ;
- 50k exceeds the current budget after the two W2 optimization cycles;
- water or rigid state can publish independently;
- save/restart is exact only with native/sidecar state;
- renderer/GPU/camera state affects physical output;
- the dry fallback can be selected after active simulation starts;
- a public schema has no field-level use in the basin consumer.

The fallback is to keep the entire water track Proposed/research-only and ship
the authored dry basin. Reducing quality or changing authority/budget is a new
decision, not a local promotion exception.

## Completion claim

Only W6 may change the main roadmap from active integration to a production
status. Each missing target/check is `NOT_RUN` and blocks that exact promotion
claim without weakening the already Accepted mandatory game path.
